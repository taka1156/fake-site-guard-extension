# Fake Site Guard

JSONで定義した正規表現を使って、正規サービスに似たホスト名を検知するChrome拡張機能です。該当するサイトを開くと拡張機能アイコンに `!` を表示し、ポップアップで正規ドメインを案内します。

ページへの警告の挿入やアクセスのブロックは行わず、閲覧中のドメインを確認する手掛かりを提供します。

## 主な機能

- **ホスト名のパターン検知** — JSONの正規表現を、大文字・小文字を区別せずに適用します。
- **バッジとポップアップでの案内** — 類似パターンを検知すると、正規ドメインとカテゴリを表示します。
- **ルール管理** — 手動追加、削除、カテゴリ別の絞り込み、確認日の更新に対応します。
- **信頼済みサイトの登録** — 誤検知したサイトを「正しいサイト」として登録し、そのホスト名への警告を除外できます。
- **JSONの入出力** — ファイル、URL、貼り付けからの取り込みと、ルール・信頼済みサイトの書き出しに対応します。
- **ルールの見直し通知** — 確認日から6か月以上経過したルールを表示し、通知で見直しを促します。

## インストール

1. このリポジトリをクローンするか、GitHubの **Code → Download ZIP** からダウンロードして展開します。

   ```sh
   git clone https://github.com/taka1156/fake-site-guard-extension.git
   ```

2. Chromeで `chrome://extensions/` を開きます。
3. **デベロッパー モード**を有効にします。
4. **パッケージ化されていない拡張機能を読み込む**を押し、`manifest.json` がある `fake-site-guard-extension` フォルダを選択します。
5. ツールバーにFake Site Guardを固定します。

ビルドや依存パッケージのインストールは不要です。Manifest V3の拡張機能として、そのまま読み込めます。

## はじめにルールを取り込む

**インストール直後はルールが空です。** 同梱のサンプルも自動では登録されません。

1. 拡張機能アイコンをクリックします。
2. **入出力**タブを開きます。
3. **ファイルから読込**で、リポジトリ内の [sample-rules.json](./sample-rules.json) を選択します。
4. **ルール**タブで取り込まれた内容を確認します。

サンプルには開発、ショッピング、エンタメ、決済、金融、通信のカテゴリがあります。掲載パターンは検知ルールの例であり、実際の悪性サイト一覧ではありません。

## 使い方

### 現在のサイトを確認する

HTTP／HTTPSのページを開くと、そのホスト名を保存済みルールと照合します。該当する場合はオレンジ色の `!` バッジが表示され、アイコンにカーソルを合わせると正規ドメインを確認できます。

**現在のサイト**タブには、閲覧中のホスト名と、取り違えている可能性がある正規ドメインを表示します。正規ドメインと完全一致する場合は登録済みの正規ドメインとして表示します。

### 誤検知したサイトを登録する

警告されたサイトが信頼できると確認できた場合は、**このサイトは正しい(登録して今後は警告しない)**を押し、確認ダイアログで登録します。

登録はホスト名の完全一致で適用されます。`example.com` を登録しても、`www.example.com` や `sub.example.com` は自動では除外されません。登録したホストは**ルール**タブから確認・解除できます。

### ルールを追加・見直す

**ルール**タブの **＋ 追加**から、正規表現、正解ドメイン、カテゴリ、確認日を入力します。既存ルールはカテゴリまたは**⏰ 要確認のみ**で絞り込めます。

確認日から6か月以上経過すると要確認として表示されます。内容を見直したら**確認済みにする**を押すと、確認日が今日に更新されます。古いルールも検知には引き続き使われます。

バックグラウンドでは1日ごとに古い検知ルールを確認し、通知は最大で7日に1回です。信頼済みサイトにも一覧で要確認の表示が付きますが、バックグラウンド通知の対象は検知ルールです。

## JSONの入出力

**入出力**タブから、次の方法で取り込めます。

| 方法 | 操作 |
| --- | --- |
| ファイル | **ファイルから読込**でJSONファイルを選択 |
| URL | JSONを返すHTTP／HTTPSのURLを入力し、**取込**を押す |
| 貼り付け | JSONをテキスト欄に貼り付け、**貼り付けを取込**を押す |

通常はルールを `id`、信頼済みサイトを `host` で統合し、同じキーの項目を上書きします。**取込時に既存ルールを置き換える**を有効にすると、有効な項目が取り込まれた配列を置き換えます。空の配列では既存データを削除しません。

不正な項目はスキップされ、取り込み結果に理由が表示されます。取り込める有効な項目がなければ、保存済みデータは更新されません。

URLからの取り込みでは、その取得先へのアクセス許可を求めます。取得は**取込**ボタンを押したときだけ行い、自動更新はしません。取得元URLと最終取り込み日が表示され、同じURLで再取得できます。

**JSONを書き出す**で、検知ルールと信頼済みサイトを `fake-site-rules-YYYY-MM-DD.json` として保存できます。

## ルールの形式

編集用のルールファイルは [rules.schema.json](./rules.schema.json) に従って作成できます。`$schema` を指定すると、対応するエディタで入力補完や検証を利用できます。

```json
{
  "$schema": "rules.schema.json",
  "version": 1,
  "rules": [
    {
      "id": "dev-github",
      "pattern": "g[i1]thub-|githu6|gihub|github-(login|auth|verify)",
      "legitimateDomain": "github.com",
      "date": "2026-10-08",
      "category": "開発",
      "note": "GitHubに似せたホスト名の検知例"
    }
  ]
}
```

| フィールド | スキーマ上の必須 | 内容 |
| --- | --- | --- |
| `$schema` | いいえ | ルールファイルの検証に使うJSON Schemaへの参照 |
| `version` | はい | 形式のバージョン。現在は `1` |
| `rules` | はい | 検知ルールの配列 |
| `rules[].id` | はい | 統合に使う識別子。英小文字・数字をハイフンで区切った形式 |
| `rules[].pattern` | はい | ホスト名に適用するJavaScriptの正規表現 |
| `rules[].legitimateDomain` | はい | 正規のホスト名。プロトコルやパスを含めない |
| `rules[].date` | はい | 追加・確認日。`YYYY-MM-DD` 形式 |
| `rules[].category` | はい | サービスのカテゴリ。自由に指定可能 |
| `rules[].note` | いいえ | 補足説明 |

### パターンを書くときの注意

- `pattern` は `/.../i` のような区切りやフラグを含めずに記述します。判定時に `i` フラグが付きます。
- 判定対象は小文字のホスト名だけです。URLのパス、クエリ、ページ本文は判定しません。国際化ドメイン名はURLパーサーによるPunycode表記で照合されます。
- JSON内ではバックスラッシュをエスケープします。たとえば正規表現の `\.` はJSON文字列では `"\\."` と書きます。
- `legitimateDomain` と信頼済みホストの除外は完全一致です。サブドメインをまとめて除外したい場合は、パターン側に除外条件を設けます。
- いずれかのルールの `legitimateDomain` と完全一致するホストは、すべてのパターン判定から除外されます。

たとえば上記のルールでは、`github-login.example` は該当し、`github.com` は除外されます。これは文字列による判定例です。

### インポートとエクスポートの形式

インポート処理は、`rules` を持つオブジェクトのほか、ルール配列そのものも受け付けます。`id` を省略すると `pattern` と `legitimateDomain` から生成され、`category` は省略可能です。これはエディタ用スキーマより緩い入力形式です。拡張機能内でJSON Schemaによる検証は行いません。

エクスポートには `version`、`exported`、`rules`、`trusted` が含まれます。`trusted` の各項目には、`host`、`date`、`category`、`similarTo`、`note` が保存されます。`similarTo` は登録時に類似していた正規ドメインの配列です。

エクスポートしたJSONはそのまま再インポートできます。ただし、現在の `rules.schema.json` は `exported` と `trusted` を定義していないため、エクスポートファイル全体の検証には使えません。

## 権限とデータの扱い

| 権限 | 用途 |
| --- | --- |
| `storage` | ルール、信頼済みサイト、取得元URL、最終取り込み日、通知日時をローカルに保存 |
| `tabs` | 閲覧中のタブのURLを読み取り、ホスト名を判定 |
| `alarms` | 古い検知ルールを定期的に確認 |
| `notifications` | ルールの見直し通知を表示 |
| 任意のHTTP／HTTPSホスト権限 | URLからのJSON取り込み時に、取得先へのアクセスを許可 |

判定はブラウザ内で実行し、閲覧URLを外部の判定サービスへ送信しません。ページ本文、フォームの入力内容、Cookieの読み取りや、ページへのスクリプト挿入も行いません。

保存先は `chrome.storage.local` です。クラウド同期は行わず、バックアップや他の環境への移行にはJSONのエクスポート／インポートを使います。URL取り込みを実行すると、指定した配信元へのネットワーク通信が発生します。

## 判定の範囲

この拡張機能は、登録したパターンに似たホスト名への気付きを補助します。パターンに該当しないサイトの安全性を保証するものではなく、未登録のなりすましやページ内容を使った攻撃は判定できません。警告の有無に加えて、実際のURLやアクセス元も確認してください。

現在のポップアップと通知の表示言語は日本語です。

## 開発

HTML、CSS、JavaScriptのみで構成され、ビルドツールは使っていません。ファイルを変更したら `chrome://extensions/` で拡張機能を再読み込みし、ポップアップを開き直して確認します。

| [manifest.json](./manifest.json) | Manifest V3の設定と権限 |
| [background.js](./background.js) | タブ変更時のバッジ更新、見直し通知 |
